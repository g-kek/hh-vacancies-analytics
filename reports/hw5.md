## Планирование CPU и вытеснение

На узле с 8 CPU задача `hh-low` заняла 6 CPU по заявке. Для наблюдения
вытеснения перед расчётом предусмотрено окно ожидания в 100 секунд.
Задача `hh-cpu-wait` с такой же заявкой и приоритетом 100 осталась
в `Pending`. Планировщик выдал `FailedScheduling` с причиной
`Insufficient cpu`.

Задача `hh-high` запросила те же 6 CPU с приоритетом 1000. Планировщик
вытеснил Pod задачи `hh-low`, о чём говорит событие `Preempted`. У
`hh-low` отключены повторы, поэтому Job завершился со статусом `Failed`.
`hh-high` выполнила расчёт, после её завершения освободились CPU и
`hh-cpu-wait` тоже успешно завершилась.

## Квота пространства имён

В `hw5-quota` установил `ResourceQuota` на 1 CPU по сумме заявок,
256 MiB по сумме лимитов памяти и два активных Pod. Первый Job занял
600m CPU и 96 MiB лимита памяти. API зарегистрировал второй Job
с такими же параметрами. При попытке создания его Pod API выдал
`Forbidden`, а контроллер Job зафиксировал `FailedCreate` из-за
превышения квоты CPU. При 1200m CPU суммарный лимит памяти всё ещё
укладывался в 256 MiB. Когда первый Pod завершился, контроллер смог
создать второй. Оба Job получили статус `Complete`.

## Как соотносятся Kubernetes, YARN и Mesos?

**Планирование и запуск.** В Kubernetes `kube-scheduler` назначает Pod
на узел с доступными ресурсами, `kubelet` запускает контейнеры, а
контроллер Job следит за завершением работы. В YARN функциональный
аналог на уровне узла — NodeManager. ResourceManager выделяет контейнеры
по запросам ApplicationMaster, который координирует задачи своего
приложения. В Mesos master распределяет ресурсы между фреймворками через
`resource offers`. Планировщик фреймворка выбирает предложения, после
чего agent запускает задачи через executor.
[Kubernetes Scheduler](https://kubernetes.io/docs/concepts/scheduling-eviction/kube-scheduler/) ·
[Архитектура YARN](https://hadoop.apache.org/docs/current/hadoop-yarn/hadoop-yarn-site/YARN.html) ·
[Архитектура Mesos](https://mesos.apache.org/documentation/latest/architecture/)

**Дефицит и приоритеты.** В Kubernetes Pod ждёт подходящий узел, а
`PriorityClass` позволяет вытеснить Pod с меньшим приоритетом.
В YARN CapacityScheduler может вернуть занятые ресурсы очередям
в соответствии с их заданными долями через политику вытеснения.
В Mesos результат зависит от политики аллокатора и фреймворка.
Например, при oversubscription QoS-контроллер агента может остановить
задачу, использующую отзываемые ресурсы.
[Приоритеты Kubernetes](https://kubernetes.io/docs/concepts/scheduling-eviction/pod-priority-preemption/) ·
[YARN CapacityScheduler](https://hadoop.apache.org/docs/current/hadoop-yarn/hadoop-yarn-site/CapacityScheduler.html) ·
[Mesos Oversubscription](https://mesos.apache.org/documentation/latest/oversubscription/)

**Квоты и ограничения.** Kubernetes проверяет `ResourceQuota` при
допуске объектов в namespace. В YARN ёмкость и максимальная ёмкость
задаются для очередей и учитываются при выделении контейнеров.
В Mesos квота задаётся для роли и влияет на распределение ресурсов
аллокатором. Поэтому очередь YARN и роль Mesos служат приблизительными
аналогами namespace для управления общим бюджетом. В эксперименте
различие между этапами видно по событиям `FailedScheduling` для уже
созданного Pod и `FailedCreate` при отказе в создании Pod.
[Квоты Kubernetes](https://kubernetes.io/docs/concepts/policy/resource-quotas/) ·
[Квоты Mesos](https://mesos.apache.org/documentation/latest/quota/)
